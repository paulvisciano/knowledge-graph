What changed

The query_knowledge_graph MCP tool previously relied on LightRAG's internal keyword extraction LLM (12B Gemma on M2 Pro) to split queries into high-level and low-level keywords before retrieval. This LLM call took 89-124 seconds per query due to slow prompt processing on the local model.

The fix replaces the LLM call with NLP-only keyword extraction — regex patterns for dates, proper noun detection, stopword filtering, and content category mapping. Keywords are pre-supplied to LightRAG's /query endpoint via hl_keywords/ll_keywords parameters, which makes LightRAG skip the keyword LLM entirely (operate.py:4036 returns immediately if keywords are pre-supplied).

This mirrors the approach used by PrivateGPT, AnythingLLM, Open WebUI, and RAGFlow (by default) — none of which use an LLM for query-time keyword extraction.

  • Before: mode=local, top_k=5, LLM keyword extraction (~120s per query)
  • After: mode=mix, top_k=5, NLP keyword extraction (~0s per query, regex only)

Why mix mode? Testing showed that mix with top_k=5 is the best all-rounder: it returns both photos and notes for date-range queries (where local returns 0 refs because Date nodes lack file_path chunks), while still finding photos for entity-specific queries. top_k=10 was tested but found to truncate context too aggressively in mix mode, reducing ref count from 3 to 1 for entity queries.

Analysis

Date Range Query — the biggest win: 124s → 1s (124x faster). The LLM keywords produced 0 refs (missed all entities), while NLP keywords found 5 refs (1 photo + 4 notes). The LLM extracted generic keywords like "past activities, dates" which didn't match entity names; NLP extracted "June", "July", "2026", "photos", "notes" which directly matched entity and chunk content.

Entity-Specific Query — 89s → 9s (10x faster). Before found 4 photo refs but 0 notes. After found 3 photo refs and 0 notes. The mix mode retrieves both entities and chunks, but the broader retrieval pulls in more entity/relation data which fills the token budget, leaving room for fewer distinct chunk file references. This is a minor trade-off: 1 fewer photo ref, but 10x faster.

Long Natural Language — 98s → 3s (33x faster). Both found 5 refs (3 photos + 2 notes). The NLP keywords correctly extracted "St Pete", "June", "July 22", "beach", "sunset", "bike", "ride", "downtown", "rained", "evening" from the 60-word transcription simulation — demonstrating that simple regex + stopword filtering handles long voice transcription queries without an LLM.
